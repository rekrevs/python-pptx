# T-0018: Transparency/alpha API for fills and colors

**Status**: DONE | **Size**: M

## Context
python-pptx has no API for color/fill transparency. The OOXML `a:alpha` element controls opacity but is completely unexposed. `color.brightness` exists as a model (using `lumMod`/`lumOff` child elements), and alpha follows the exact same pattern. This is a frequently requested feature — upstream has an unmerged transparency PR (Sep 2025).

## Acceptance Criteria
- [x] `color.alpha` property (read/write, float 0.0-1.0 where 1.0=opaque)
- [x] Works with solid fills on shapes
- [x] Works with font color
- [x] OXML support for `a:alpha` element on color types (srgbClr, schemeClr)
- [x] Unit tests for alpha get/set
- [x] BDD acceptance test for transparency round-trip

## Approach
1. Register `a:alpha` element with `CT_Percentage` in `src/pptx/oxml/__init__.py` (same as `a:lumMod`)
2. Add `alpha = ZeroOrOne("a:alpha")` on `_BaseColorElement` in `src/pptx/oxml/dml/color.py`
3. Add `add_alpha(value)` and `clear_alpha()` methods on `_BaseColorElement`
4. Add `alpha` property on `_Color` base class in `src/pptx/dml/color.py` (read from `a:alpha` child, default 1.0)
5. Add `alpha` property on `ColorFormat` (delegates to `_color.alpha`, validates 0.0-1.0)
6. Unit tests in `tests/dml/test_color.py`
7. BDD acceptance test in `features/` for transparency

### Design Decisions

- Reused `CT_Percentage` for `a:alpha` (same structure as lumMod/lumOff)
- Alpha = 1.0 removes element entirely (matches PowerPoint behavior)
- `_NoneColor.alpha` returns 1.0 default; setting raises ValueError
