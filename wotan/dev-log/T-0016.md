# T-0016: Volume stock charts (VHLC/VOHLC)

**Status**: READY
**Phase**: —

## Context

Stock charts with volume (VHLC and VOHLC) are multi-plot charts that combine a bar chart for volume data with a stock chart for price data. These require a secondary axis and more complex XML structure than simple HLC/OHLC charts.

The enum values exist (`XL_CHART_TYPE.STOCK_VHLC`, `XL_CHART_TYPE.STOCK_VOHLC`) but are not registered in the `ChartXmlWriter` factory, so attempting to create them raises `NotImplementedError`.

## Acceptance Criteria

- [ ] _VolumeStockChartXmlWriter class implemented (or extend _StockChartXmlWriter)
- [ ] STOCK_VHLC and STOCK_VOHLC registered in ChartXmlWriter factory
- [ ] Multi-plot XML structure: barChart + stockChart in plotArea
- [ ] Secondary value axis for volume data
- [ ] Unit tests for VHLC/VOHLC XML generation
- [ ] BDD acceptance tests for volume stock chart creation
- [ ] All tests pass

- `src/pptx/chart/chart.py` — `chart_type` (line 80-87) uses `plots[0]`, which for VHLC/VOHLC would be the barChart (first in document order). This means chart type detection needs work for round-trip support.
- `tests/chart/test_xmlwriter.py` — `Describe_StockChartXmlWriter` (line 319-332) has two tests using `make_stock_chart_data` helper and `snippet_text` for expected XML. Convention: snippets in `tests/test_files/snippets/` with naming like `2x4-stock-vhlc.txt`.
- `features/shp-shapes.feature` — Stock chart BDD at line 148-159 uses `When I add a <type> chart with 2 categories` step, defined in `features/steps/chart.py` at line 133.

**Relevant prior work:**
- T-0010 added HLC/OHLC stock chart support, establishing the `_StockChartXmlWriter` pattern.
- T-0011 added surface charts with 3 axes (catAx, valAx, serAx), showing the pattern for multi-axis chart writers.

**Key constraints:**
- Volume stock charts are **multi-plot**: `<c:barChart>` for volume + `<c:stockChart>` for price data.
- The barChart must reference the **secondary value axis** (right side) and share the same **category axis**.
- The stockChart references the **primary value axis** (left side) and the same shared category axis.
- This is the first multi-plot chart writer in the codebase. No existing writer generates two xChart elements in one plotArea.
- `CategoryChartData` should be reusable — the first series is volume, the rest are stock series, following OOXML convention.
- The `_upDownBars_xml` property already handles VOHLC correctly (line 1379).

**OOXML structure for VHLC/VOHLC (verified from ECMA-376 and task hypothesis):**
```xml
<c:plotArea>
  <c:barChart>
    <c:barDir val="col"/>
    <c:grouping val="clustered"/>
    <c:ser><\!-- Volume series (idx=0) --></c:ser>
    <c:axId val="CAT_AX_ID"/>
    <c:axId val="SEC_VAL_AX_ID"/>
  </c:barChart>
  <c:stockChart>
    <c:ser><\!-- H/L/C or O/H/L/C series (idx=1..3 or 1..4) --></c:ser>
    <c:hiLowLines/>
    <c:upDownBars>...</c:upDownBars>  <\!-- only for VOHLC -->
    <c:axId val="CAT_AX_ID"/>
    <c:axId val="PRI_VAL_AX_ID"/>
  </c:stockChart>
  <c:catAx>
    <c:axId val="CAT_AX_ID"/>
    <c:crossAx val="PRI_VAL_AX_ID"/>
  </c:catAx>
  <c:valAx>   <\!-- Primary (price) on left -->
    <c:axId val="PRI_VAL_AX_ID"/>
    <c:crossAx val="CAT_AX_ID"/>
  </c:valAx>
  <c:valAx>   <\!-- Secondary (volume) on right -->
    <c:axId val="SEC_VAL_AX_ID"/>
    <c:axPos val="r"/>
    <c:crossAx val="CAT_AX_ID"/>
    <c:crosses val="max"/>
  </c:valAx>
</c:plotArea>
```

### Approaches Considered

#### 1. New `_VolumeStockChartXmlWriter` subclass of `_BaseChartXmlWriter` (P = 0.82)

**Description**: Create a new writer class `_VolumeStockChartXmlWriter` that generates the complete multi-plot XML, including both `<c:barChart>` and `<c:stockChart>` elements in a single `xml` property. Register STOCK_VHLC and STOCK_VOHLC to this new class in the factory. The volume series (first in the data) goes to barChart; the remaining series go to stockChart. Reuse `_CategorySeriesXmlWriter` for individual series XML generation, just like the existing stock writer does.

| Criterion | Score | Notes |
|-----------|-------|-------|
| Pattern alignment | + | Follows same per-chart-type writer pattern as all others |
| Elegance | + | Clean separation from HLC/OHLC; different enough XML to justify own class |
| Surface area | + | 1 new class in xmlwriter.py + 2 factory entries + tests |
| Risk | + | Low — isolated new code, does not touch existing HLC/OHLC logic |
| Testability | + | Snippet-based test exactly like existing stock tests |
| Reversibility | + | Delete the class and factory entries to revert |

**Pros**: Clean separation of concerns. Volume stock charts generate fundamentally different XML (two plot elements, three axes) compared to plain stock charts. A separate class avoids complex conditional branching. Follows established pattern where each chart category gets its own writer class.

**Cons**: Some duplication with `_StockChartXmlWriter` for the stockChart portion and common XML boilerplate (header, footer, legend). But this is consistent with how all other writers in the file are structured — each has its own complete XML template.

#### 2. Extend existing `_StockChartXmlWriter` with conditionals (P = 0.68)

**Description**: Add conditional logic to the existing `_StockChartXmlWriter.xml` property to generate barChart + secondary axis when chart type is VHLC/VOHLC. The `_ser_xml` would split: first series to bar, rest to stock. Add `_bar_chart_xml`, `_secondary_val_ax_xml` helper properties.

| Criterion | Score | Notes |
|-----------|-------|-------|
| Pattern alignment | -- | No other writer has multi-chart conditional logic |
| Elegance | -- | Makes simple class complex; string template becomes hard to follow |
| Surface area | + | 1 file modified, no new class |
| Risk | -- | Could break existing HLC/OHLC if conditionals are wrong |
| Testability | + | Same snippet-based testing |
| Reversibility | -- | Changes interleaved with existing code |

**Pros**: No new class; keeps all stock logic together.

**Cons**: The `xml` property would need major conditional branching for three fundamentally different structures (HLC vs OHLC vs VHLC vs VOHLC). The string template approach used throughout the codebase works well for linear XML but becomes fragile when entire sections (barChart, secondary axis) are conditionally inserted. Risk of breaking existing HLC/OHLC tests. The `_upDownBars_xml` already has VOHLC awareness, but extending the main template is a different matter entirely.

#### 3. Shared base class for stock writers (P = 0.72)

**Description**: Refactor `_StockChartXmlWriter` into a shared `_BaseStockChartXmlWriter` with common methods (`_stock_ser_xml`, `_cat_ax_xml`, `_upDownBars_xml`). Create `_VolumeStockChartXmlWriter` subclass that overrides `xml` to add barChart + secondary axis, calling shared methods for the stock portion.

| Criterion | Score | Notes |
|-----------|-------|-------|
| Pattern alignment | -- | No other chart family uses inheritance hierarchy |
| Elegance | + | Good code reuse for shared stock logic |
| Surface area | -- | Refactors existing class + adds new hierarchy |
| Risk | -- | Refactoring existing working code; could break HLC/OHLC |
| Testability | + | Same snippet-based testing |
| Reversibility | -- | Structural refactor is harder to undo |

**Pros**: Eliminates duplication for shared stock chart elements (hiLowLines, upDownBars, stock series XML). Clean inheritance.

**Cons**: No other writer family uses this pattern. The shared code is actually small (upDownBars logic, hiLowLines). Refactoring a working class risks regressions. The codebase convention is clearly "flat hierarchy — each writer is independent."

#### 4. Composition: Volume writer delegates to stock writer internally (P = 0.70)

**Description**: Create `_VolumeStockChartXmlWriter` that internally creates a `_StockChartXmlWriter` to generate the stockChart portion, then wraps it with barChart and secondary axis XML. The stock writer would need a method that returns just the `<c:stockChart>...</c:stockChart>` fragment.

| Criterion | Score | Notes |
|-----------|-------|-------|
| Pattern alignment | -- | No writer uses composition pattern |
| Elegance | - | Awkward: would need to extract partial XML from another writer |
| Surface area | -- | Modify _StockChartXmlWriter + create new class |
| Risk | - | Extracting partial XML from string templates is fragile |
| Testability | + | Same snippet-based testing |
| Reversibility | - | Changes to existing class required |

**Pros**: Reuses existing stock chart XML generation.

**Cons**: The string-template approach does not lend itself to composition. You cannot easily extract "just the stockChart fragment" from a writer whose `xml` property returns the complete `<c:chartSpace>` document. Would require refactoring the stock writer to expose fragment methods, which no other writer does.

### Recommendation

**Selected**: Approach 1 — New `_VolumeStockChartXmlWriter` subclass of `_BaseChartXmlWriter`

**Rationale**:
- Highest confidence (P = 0.82) due to clean isolation from existing code
- Follows the established codebase pattern where each chart category gets its own flat writer class — no inheritance hierarchies, no composition, just a class with an `xml` property that returns the complete document
- Zero risk to existing HLC/OHLC functionality since no existing code is modified (beyond adding two factory entries)
- The duplication of boilerplate XML (chartSpace wrapper, legend, txPr) is consistent with every other writer in the file — this is a deliberate design choice in the codebase, not an oversight
- Testability is straightforward: create expected XML snippets and compare via `snippet_text`

**Key implementation notes**:
1. **New class**: `_VolumeStockChartXmlWriter(_BaseChartXmlWriter)` in `xmlwriter.py`
2. **Factory registration**: Add `XL_CT.STOCK_VHLC: _VolumeStockChartXmlWriter` and `XL_CT.STOCK_VOHLC: _VolumeStockChartXmlWriter` to the factory dict
3. **Series splitting**: First series in `chart_data` is Volume (goes to `<c:barChart>`); remaining series go to `<c:stockChart>`. Use `_CategorySeriesXmlWriter` for each series, same as existing pattern.
4. **Axis IDs**: Use distinct IDs for catAx, primary valAx, and secondary valAx. The secondary axis has `<c:axPos val="r"/>` and `<c:crosses val="max"/>`.
5. **The barChart** needs `<c:barDir val="col"/>`, `<c:grouping val="clustered"/>`, and references catAx + secondary valAx.
6. **upDownBars**: The existing `_StockChartXmlWriter._upDownBars_xml` logic already handles VOHLC. Copy this pattern to the new class.
7. **Test snippets**: Create `2x4-stock-vhlc.txt` and `2x5-stock-vohlc.txt` (following `{cats}x{series}-{type}.txt` naming convention)
8. **Test helper**: Extend `make_stock_chart_data` or create `make_volume_stock_chart_data` that adds a Volume series before the price series.
9. **BDD**: Add `Stock VHLC` and `Stock VOHLC` to the step definition mapping and feature scenario table.
10. **Chart type detection** (read-back): For now, `chart_type` will report the barChart's type when reading VHLC/VOHLC back. Full round-trip detection (recognizing barChart+stockChart combo as STOCK_VHLC/VOHLC) is a separate enhancement that can be addressed later. The acceptance criteria focus on chart **creation**, not read-back type identification.

**Fallback**: If the single-class approach produces overly long XML templates, fall back to Approach 3 (shared base class). The function signatures and test structure would remain the same.

### Design Decisions

**Separate writer class (`_VolumeStockChartXmlWriter`)**: Volume stock charts generate fundamentally different XML (two plot elements, three axes) vs plain stock charts (one plot, two axes). A separate class keeps each writer focused and avoids complex conditionals in the existing `_StockChartXmlWriter`. This follows the flat-hierarchy pattern used by all other chart writers in the codebase.

**Axis IDs**: Used three deterministic IDs: `2118791784` (catAx, shared with existing stock charts), `2140495176` (primary valAx for price, same as existing), and `2107640568` (new secondary valAx for volume). The secondary axis uses `<c:axPos val="r"/>` and `<c:crosses val="max"/>` to position it on the right side.

**Bar series without marker/smooth**: The volume series in the barChart omits `<c:marker>` and `<c:smooth>` elements since those are line-chart-specific. The stock series retain them, matching the existing stock chart pattern.

**Chart type detection**: Updated `Chart.chart_type` to detect the barChart+stockChart combination and differentiate VHLC (3 stock series) from VOHLC (4 stock series) based on the number of `c:ser` elements in the stockChart. This enables correct round-trip type identification.

**upDownBars handling**: VOHLC includes `<c:upDownBars>` (same as OHLC), VHLC does not (same as HLC). The `_upDownBars_xml` property follows the same pattern as the existing stock chart writer.
